# Post Explorer

Flutter-приложение для просмотра, поиска и создания постов.
API: [JSONPlaceholder](https://jsonplaceholder.typicode.com).

Стек: **Dio** + **Retrofit** + **json_serializable** + **SharedPreferences** (кэш) + **Provider** (состояние).

## Запуск

```bash
flutter pub get
dart run build_runner build   # генерация *.g.dart
flutter run -d chrome   # или -d windows (нужна Visual Studio с C++)
```

Тесты:

```bash
flutter test
```

## Архитектура

```
lib/
├── core/
│   ├── network/
│   │   ├── dio_client.dart        # единственный Dio: baseUrl, таймауты, интерсепторы
│   │   └── api_interceptor.dart   # технические заголовки + лог ошибок
│   └── error/
│       └── app_exception.dart     # единая ошибка: нет сети / таймаут / 4xx / 5xx / JSON / неизвестная
├── data/
│   ├── models/                    # Post, Comment, User (+ вложенные Address, Company)
│   ├── remote/post_api.dart       # Retrofit: описание 6 запросов
│   ├── local/post_cache.dart      # кэш постов в SharedPreferences
│   └── repositories/
│       └── post_repository.dart   # единая точка доступа к данным
├── presentation/
│   ├── screens/                   # список, детали, создание поста
│   ├── widgets/                   # карточка поста, Loading/Error/Empty
│   └── state/posts_provider.dart  # состояние списка (ChangeNotifier)
└── main.dart
```

Поток данных: **UI → Provider → Repository → (Retrofit API → Dio) / Cache**.
UI никогда не обращается к Dio напрямую.

## API-запросы (Retrofit)

| № | Метод | Endpoint | Где используется |
|---|-------|----------|------------------|
| 1 | GET | `/posts?_page=1&_limit=10` | список с пагинацией |
| 2 | GET | `/posts/{id}` | экран деталей |
| 3 | GET | `/posts?userId={id}` | фильтр по автору |
| 4 | GET | `/posts/{id}/comments` | комментарии на экране деталей |
| 5 | POST | `/posts` | создание поста |
| + | GET | `/users`, `/users/{id}` | список авторов, информация об авторе |

## Состояния экрана списка

| Состояние | Когда |
|-----------|-------|
| `loading` | первая загрузка, кэша нет |
| `success` | данные с сервера получены |
| `error` | ошибка и нет сохранённых данных — кнопка «Повторить» |
| `cached` | показаны сохранённые данные (жёлтая плашка): идёт обновление или сервер недоступен |
| empty | список пуст или поиск ничего не нашёл |

Подгрузка следующей страницы имеет **своё** состояние (`isLoadingMore`, `loadMoreError`),
отправка формы — своё (`_isSubmitting`). Общего флага `isLoading` нет.

## Поведение кэша

- **Первый запуск** — кэша нет: крутится индикатор, затем список с сервера, он сохраняется в кэш.
- **Повторное открытие** — сразу показывается кэш (плашка «Показаны сохранённые данные. Обновление...»), параллельно идёт запрос, после ответа список заменяется свежим и кэш обновляется.
- **Нет интернета** — показываются закэшированные посты и сообщение «Нет подключения к интернету». Последний успешный результат не удаляется. Если кэша нет — экран ошибки с кнопкой «Повторить».
- **Pull-to-refresh** — потянуть список вниз для ручного обновления.

## Пагинация и фильтры

- Загружается по 10 постов, следующая страница — при прокрутке к концу списка.
- Повторная загрузка той же страницы блокируется (`if (isLoadingMore) return`), дубликаты по `id` отбрасываются.
- При смене автора страницы сбрасываются, а ответы на старые запросы игнорируются
  (счётчик `_generation`), поэтому старые результаты не смешиваются с новыми.
- **Поиск по заголовку и сортировка по ID работают по загруженным постам** — об этом написано в интерфейсе под полем поиска.

## Создание поста

Валидация: title 5–100 символов, body 10–1000, автор из списка. Во время отправки кнопка заблокирована.
После ответа показывается объект, который вернул сервер, а пост добавляется в список
с пометкой **«создан локально»**: JSONPlaceholder принимает POST, но не сохраняет пост на самом деле.

## Зачем каждый слой

- **Dio** — HTTP-клиент: таймауты, интерсепторы (заголовки, логи), единый формат ошибок `DioException`.
- **Retrofit** — по аннотациям (`@GET`, `@Query`, `@Path`, `@Body`) генерирует код запросов. Не нужно вручную собирать URL и парсить ответ.
- **json_serializable** — генерирует `fromJson`/`toJson` для моделей. Нет ручного парсинга, ошибки в названиях полей ловит компилятор.
- **Repository** — прячет от UI, откуда берутся данные (сеть или кэш), и превращает любые ошибки в `AppException` с понятным текстом.
